# 机关事务后勤管理系统 — 部署手册

> 适用版本：logistics-backend 1.0.0 + 前端构建产物（frontend/dist）
> 编写日期：2026-08-24

---

## 1. 系统概述

机关事务后勤管理系统，覆盖以下业务模块：

| 模块 | 功能 | 主要页面 |
| --- | --- | --- |
| 公物仓（GC） | 资产入仓/借用/归还/处置/调拨申请与审批 | AssetApply、BorrowApply、ReturnApply、DisposeApply、TransferApply、AssetList |
| 车辆管理（CL） | 用车申请/审批、派车、车辆档案、维修、定位轨迹 | ApplyManage、DispatchManage、VehicleManage、RepairManage、TrackMonitor |
| 公寓管理（GY） | 房间管理、入住申请/审批/退房、保洁、维修 | RoomManage、OccupantManage、CleaningManage、RepairManage |
| 食堂管理（ST） | 物资台账、采购、入库/出库/盘点、报餐、厨余 | MaterialManage、PurchaseManage、InventoryManage、MealReserve、MealStatistics |
| 一卡通（PAY） | 账户管理、充值、消费、交易流水 | CardManage |
| 系统能力 | 消息中心、操作日志、首页驾驶舱 | MessageCenter、LogQuery、Dashboard |

### 技术栈

- **后端**：Spring Boot 2.7.18（源码编译级别 Java 8，可在 JDK 8~17 运行）、Spring Security + JWT、Spring Data JPA、Lombok、PostgreSQL
- **前端**：Vue 3、Element Plus 2、Vue Router 4（history 模式）、Vite 6、ECharts、高德地图 JS API
- **数据存储**：PostgreSQL（当前版本 17，建议 ≥ 14）

### 部署架构（推荐）

浏览器通过 Nginx 访问系统：Nginx 负责托管前端静态页面（打包后的 dist 内容），并把接口路径（以 /api 开头）反向代理到后端的 8080 端口；后端连接本机 PostgreSQL 数据库 JYGDataBase。

## 3. 打包构建

### 3.1 后端打包

在项目根目录执行 Maven 打包命令，跳过测试，产物为 target 目录下的 logistics-backend-1.0.0.jar。

### 3.2 前端打包

先在 frontend 目录安装依赖（首次或依赖变化时），再执行构建命令，产物为 frontend/dist 文件夹（含 index.html 与 assets 目录），部署时把 dist 里的内容整体拷贝到 Nginx 站点目录即可。

---

## 4. 数据库部署

### 4.1 准备

同目录下的 database.sql 由 pg_dump 生成，包含全部表结构、基础数据与账号，可直接用于初始化。

### 4.2 初始化步骤

第一步，用 psql 登录 PostgreSQL，创建一个名为 JYGDataBase 的空数据库（若已存在可跳过）。

第二步，将 database.sql 导入该数据库。导入命令为 psql 连接 JYGDataBase 后执行 -f database.sql（Linux 上可切换到 postgres 系统用户后执行）。

注意两点：

- database.sql 自带先删后建的逻辑，可重复执行，适合覆盖式初始化。
- 若服务器 PostgreSQL 账号密码不是 postgres/root，需要同步修改后端配置（见第 5 节）。

## 5. 后端部署

### 5.1 启动

用 java -jar 命令直接启动 logistics-backend-1.0.0.jar，默认监听 8080 端口。

### 5.2 数据库连接配置

默认连接配置已打包在 jar 内（数据库地址为 localhost:5432/JYGDataBase，用户 postgres，密码 root）。如果数据库地址或密码不同，**无需重新打包**，启动时追加配置参数覆盖即可：依次指定数据库地址、用户名、密码三个参数。

### 5.3 验证后端

向后端登录接口发送 POST 请求（用户名 admin，密码 admin123），若返回结果中 code 为 200 且包含 token，说明后端与数据库均正常。

## 6. 前端部署（Nginx）

> 本机已安装并配置完成：Nginx 位于 deploy\nginx 目录，前端站点目录为 deploy\nginx\html，80 端口监听中，/api 已代理到后端 8080。

### 6.1 配置要点

把 frontend/dist 里的所有文件拷贝到 Nginx 站点目录（本机为 deploy\nginx\html，即安装目录下的 html 文件夹），然后修改 Nginx 配置（conf\nginx.conf），包含以下三块：

1. **站点基础配置**：监听 80 端口，root 指向上述站点目录，index 设置为 index.html。
2. **接口反向代理**：凡是 /api 开头的请求，一律转发到 http://localhost:8080，并透传原始请求头（Host、X-Real-IP 等）。这是系统能否正常取数的关键，前端请求默认都带 /api 前缀，漏配会导致全部接口失败。
3. **路由回退**：因为前端使用 history 路由模式，需要把不存在的路径统一回退到 index.html（即 try_files 指向 /index.html），否则刷新子页面会 404。

另外可对 assets 目录配置 30 天静态缓存，提升加载速度。

### 6.2 启动与重载

在 Nginx 安装目录（本机为 deploy\nginx）下执行 nginx.exe：

- 启动：nginx.exe（带 -p 参数指定安装目录，本机为 nginx.exe -p deploy\nginx 的绝对路径）
- 重载配置：nginx.exe -s reload（修改 nginx.conf 后执行，使配置生效）
- 停止：nginx.exe -s stop
- 检查配置：nginx.exe -t（测试配置文件语法，提示 syntax is ok 即为正常）

### 6.3 开放防火墙

Windows 服务器需放行 80（网页）、8080（后端）、5432（数据库）三个端口。使用管理员 PowerShell 执行 netsh advfirewall 放行命令，分别针对三个端口添加入站规则。

## 10. 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 页面打不开 / 白屏 | Nginx 是否启动、80 端口是否放行；站点目录是否包含 index.html |
| 接口 404 / 请求失败 | /api 是否已代理到后端 8080；后端是否启动 |
| 登录提示“登录已过期” | 后端未启动或接口代理失败；查看浏览器网络请求 |
| 登录后 403 | 当前账号角色未被接口放行（换 admin 或 zhangwei 验证） |
| 数据库连接失败 | 检查启动参数中的数据库地址、账号、密码；确认 PostgreSQL 服务已启动 |
| 中文乱码 | 数据库导入须为 UTF-8 编码；Windows 控制台执行 psql 前切换代码页或设置 PGCLIENTENCODING=UTF8 |
| 局域网其他电脑无法访问 | 放行 80/8080 端口；确认防火墙已开；Nginx 监听不要只绑定 127.0.0.1 |
